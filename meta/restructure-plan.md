## 抽出した構成上の問題

### 重複・類似ページ
- `routing`: BFD ハードウェアオフロードが `bfd-hw-offload.md` と `bfd-hw-offload-for-bgp-session.md` に分かれ、片方は BGP session 観点、片方は BfdOrch 観点で近い。
- `routing`: EVPN/VXLAN は `routing/evpn-vxlan-*` と `overlay/vxlan-sonic.md` にまたがり、読者の入口が分散している。
- `acl-qos`: buffer / watermark / reclaim reserved buffer / dynamic headroom が複数ページに分かれ、QoS バッファ系としてまとまった入口がない。
- `system`: CRM は `critical-resource-monitoring.md` と `critical-resource-monitoring-in-sonic.md` が要件と実装で近く、index 側で関係を明示する必要がある。
- `architecture/system/platform`: sFlow、SAI failure、SmartSwitch HA などが area をまたぐ。誤分類とは断定しないが、index と関連リンクで横断導線が必要。

### 粒度ばらつき
- HLD 移植ページ、テストプラン、実装メモ、リファレンスが同じ階層で並ぶ area がある。特に routing / system / architecture はページ数が多く、単純なファイル名順では目的別に探しにくい。
- `reference` は CLI / CONFIG_DB / YANG の粒度が揃っている一方、機能別章からの相互リンクが少ないため、設定名から設計へ戻りづらい。
- `internals` は 12 ページで少ないが、system/architecture に内部実装寄りページが残っており、将来の移動候補がある。

### 命名不統一
- slug に `hld`, `high-level-design-document`, `design-doc`, `test-plan`, `omit-in-toc` が混在する。既存 URL 保持のため今回はファイル名変更せず、index と `.pages` で表示順を整える。
- タイトルは日本語の説明的タイトルと英語原題が混在する。本文や frontmatter は触らず、index 側に読み替え可能な一覧を置く。

### index / nav / 相互リンク
- 10 area の多くの `index.md` が「準備中」のままで、455 ページに対する入口として機能していない。
- top-level `.pages` は area 順のみ定義済みだが、area 内は `...` による自動順で、BGP / VRF / VLAN / SmartSwitch など意味的まとまりが出ない。
- CONFIG_DB、CLI、HLD の 3 種類が相互に参照されておらず、運用者が「設定テーブル → CLI → 設計背景」をたどりにくい。

### discrepancy-found の可視化
- `discrepancy-found` は全体で 39 ページあるが、一覧ビューがない。各 area index に該当ページの短い一覧を置くのが最小コストで効果が高い。

## 改善計画

### High
- 10 area の `index.md` を更新し、概要、検証分布、`discrepancy-found` / `hld-only`、全ページ一覧を表示する。
- `.pages` を area ごとに意味順へ変更し、頻出トピックを先に出す。URL 変更は行わない。
- CONFIG_DB ↔ CLI ↔ HLD の高頻度導線を、ページ末尾の「関連ページ」セクションとして追加する。対象は BGP、interface/port、VLAN、VRF、VXLAN、ACL、sFlow、NTP/Syslog/TACACS、kdump など。

### Medium
- discrepancy-found 専用 index またはタグページを作り、area 横断で一覧できるようにする。
- `*-test-plan` ページを index 上でテスト計画として分け、仕様ページと並列に見えないようにする。
- SmartSwitch / DASH / Dual ToR など area 横断クラスタを明示する横断ページを検討する。

### Low
- slug 命名規則を将来方針として文書化する。ただし既存 URL 破壊を避けるため、今回の restructure では rename しない。
- hld-only ページの再検証優先順位を area index から queue に反映する。
